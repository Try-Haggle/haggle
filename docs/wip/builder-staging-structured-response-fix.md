## 사용자 결과와 원인

목표 $680, 최대 예산 $850를 설정할 때 AI가 내부 메모 일부를 잘못 반환해도
유효한 예산과 응답을 유지하고, 서버가 대기 질문을 다시 구성한다. 다른 실패로
응답을 못 받으면 `Try again`으로 같은 금액을 재전송한다. 사용자 메시지는 중복되지 않는다.

2026-10-01 19:40 MDT 스크린샷과 일치하는 Railway staging 로그를 확인했다.
`2026-10-02T01:40:18.465Z`, `req-1j`의 `ZodError`는
`memory.structured.pendingSlots[0..4]`에서 객체 대신 문자열을 받았다고 기록했다.
AI 응답의 선택적 내부 메모 검증 실패가 전체 turn의 502로 이어졌다.
별도로 예산 위젯의 실패 처리에는 일반 채팅에 있던 `retryText`가 없었다.

## 변경 흐름과 보호장치

- 응답 스키마에서만 잘못된 `memory.structured`를 생략 처리한다. 기존 검증된
  내부 메모를 먼저 사용하고 기존 서버 로직으로 질문·분류·충돌 정보를 다시 만든다.
- 프롬프트에 내부 메모는 반환하지 않도록 명시한다.
- 요청 스키마와 예산·선호·필수 조건 등 나머지 응답 필드 검증은 유지한다.
  깨진 JSON·누락된 필수 메모는 기존 HAGA-88의 한 번 재시도와 실패 처리를 따른다.
- 예산 위젯 실패 버블에 재시도할 원문을 붙인다. 재시도는 현재 저장된 예산으로
  기존 채팅 경로를 사용하며 실패 버블을 교체한다.
- 서버 요구 질문과 이전 범위 적용 거절 결정이 보존되는 회귀 테스트를 추가했다.
