1협상 에이전트란 무엇인가 — 팀의 멘탈모델

핵심 정의: "Agent"는 협상 에이전트입니다. 프리셋(전반적인 협상 스타일) + 태그별 세부값(카테고리 특화 조건) + LLM 채팅으로 조정된 유저 전략값, 이 모든 것이 하나의 협상 에이전트 안에 들어갑니다.

협상 에이전트 구성 — 빌드 순서
1
Negotiation Agent Preset 선택
전반적인 협상 스타일을 결정. 에이전트의 기본 뼈대.
🏹 Hunter — 공격적 앵커 🤝 Closer — 빠른 딜 클로즈 🔍 Verifier — 신뢰 중심 ⚖️ Balancer — 균형
2
Negotiation Agent Builder Chat (LLM 채팅)
유저와 대화하며 에이전트를 세부 조정.
① 태그별 필드값 수집 (예: 아이폰이면 → 배터리 용량, 액정 상태, 잠금 해제 여부)
② 프리셋 파라미터 미세 조정 (예산 범위, 목표 가격, 협상 강도 등)
③ Lumen 보이스 프로필이 채팅 말투를 결정
budgetMax (예산 상한) targetPrice (목표 가격) mustHave (필수 조건) avoid (제외 조건) riskStyle (위험 감수도) 태그 카테고리 필드값들
3
Negotiation Agent Profile 저장
프리셋 + 채팅 조정값 + 태그 필드값 전부를 하나의 에이전트 프로필로 저장.
DB의 negotiation_agents 테이블에 저장돼야 함 (현재: localStorage에만).
4
실제 협상 시 사용
협상 세션 시작 시 에이전트 프로필에서 값을 읽어 strategySnapshot에 저장.
협상 엔진이 strategySnapshot을 기반으로 라운드를 실행.
2현재 문제 — 같은 단어, 다른 의미

문제: 아래 단어들이 코드 전반에서 각자 다른 의미로 쓰이고 있습니다. 팀원이 파일 이름만 보고 역할을 알 수 없고, 잘못된 곳에 코드를 추가하거나 같은 개념을 중복 구현하는 문제가 발생합니다.

"advisor"
— 코드에서 4가지 다른 의미로 사용됨
현재 이름위치실제 의미
advisor.ts routes/advisor.ts 분쟁 해결 AI 채팅. 협상 종료 후 분쟁 발생 시 buyer/seller와 대화하는 별개 시스템. /disputes/:id/advisor/chat
analyzeAdvisorTurn() intelligence-demo.ts 에이전트 빌더 채팅 처리. 유저 메시지 → LLM → AdvisorMemory 업데이트. 협상 에이전트 만들 때 사용.
advisorConfig skill_presets DB 컬럼 에이전트 전략 설정값 저장 필드. 채팅에서 추출한 전략값이 저장돼야 할 JSONB 컬럼. 현재 비어있음.
advisorSkillId skill_presets DB 컬럼 어떤 AI 스킬 모듈을 쓸지 지정하는 텍스트 ID. 협상 에이전트 정의의 일부.
"preset"
— 2가지 다른 레벨에서 사용됨
현재 이름위치실제 의미
NegotiationPreset packages/shared 시스템 정의 협상 스타일 프리셋 (hunter/closer/verifier/balancer). alpha, beta, weights 등 협상 행동 파라미터 포함. 코드에 하드코딩. → NegotiationAgentPreset으로 통일 예정.
skill_presets DB 테이블 유저가 커스텀한 협상 에이전트를 서버에 저장하는 테이블. "skill"이란 이름이 협상 에이전트와 무관해 보임. 현재 아무도 여기에 write하지 않음.
"agent"
— 3가지 다른 수준에서 사용됨
현재 이름위치실제 의미
AgentProfile shared/agent-stats/types.ts 유저가 저장한 협상 에이전트 타입. 현재 localStorage에만 저장됨. 전략값(budgetMax 등) 포함 안 됨. DB 저장 없음.
AgentBuilderValue AgentBuilder.tsx 에이전트 빌더 UI의 임시 상태. effectivePreset + overrides + dirty 플래그. 저장 전까지는 메모리에만 존재.
Lumen 페르소나 (agent_id로 지정) lumen-persona-profiles.ts 에이전트 빌더 채팅에서 AI가 어떤 말투로 대화할지만 결정하는 보이스 프로필. 협상 동작(alpha, beta 등)과 완전히 무관. 12개 하드코딩.
"memory"
— 완전히 다른 2개 시스템에서 사용됨
현재 이름위치실제 의미
AdvisorMemory advisor-demo-types.ts 에이전트 빌더 채팅 중 LLM이 매 턴마다 업데이트하는 구조체. budgetMax, targetPrice, mustHave, riskStyle 등 포함. 현재 localStorage에만 임시 저장.
user_memory_cards DB 테이블 / intelligence.ts 유저의 장기 선호도를 기억하는 별도 시스템. 리스팅 추천, 반복 질문 방지 등에 활용 예정. 협상 에이전트와 직접 연결 없음. Intelligence 레이어 전용.
3레이어별 이름 통일안

원칙: 이름만 보고 어느 레이어, 어떤 기능인지 알 수 있어야 합니다. 아래는 제안이며, 팀 합의 후 일괄 리네이밍합니다. 당장 코드 변경 없음.

레이어 A — 협상 에이전트 (Negotiation Agent)
현재제안종류이유
skill_presets → negotiation_agents DB 테이블 "skill"이 협상 에이전트와 무관하게 느껴짐. 역할 명확히.
AgentProfile → NegotiationAgent 타입 협상 에이전트임을 명시. "Profile"이 모호함.
AgentBuilderValue → NegotiationAgentDraft 타입 저장 전 임시 상태임을 "Draft"로 명시.
localAgents (localStorage) → draftNegotiationAgentStore 유틸 협상 에이전트 임시 보관소임을 명확히. "local"이 의미 불명확.
advisorConfig (DB 컬럼) → negotiation_agent_builder_chat_config DB 컬럼 이름만 보고 역할 파악 가능: "협상 에이전트 빌더 채팅으로 생성된 설정값". "advisor"가 어떤 advisor인지 불명확했고 "strategy"만으로도 부족함.
advisorSkillId (DB 컬럼) → negotiation_agent_llm_skill_id DB 컬럼 협상 에이전트가 사용할 LLM 스킬 모듈 ID임을 명확히.
NegotiationPreset → NegotiationAgentPreset 타입 협상 에이전트의 기본 뼈대(프리셋)임을 명시. "Agent" 없이는 무엇의 프리셋인지 불명확.
NegotiationPresetId → NegotiationAgentPresetId 타입 동상.
레이어 B — Negotiation Agent Builder Chat
현재제안종류이유
intelligence-demo.ts → negotiation-agent-builder-chat.ts 파일 "demo" 제거. 이름만 보고 Negotiation Agent 빌드 채팅 처리 파일임을 바로 알 수 있게.
StrategyChat (컴포넌트) → NegotiationAgentBuilderChat 컴포넌트 "Strategy"가 너무 광범위. Negotiation Agent 빌더용 채팅임을 명시.
analyzeAdvisorTurn() → processNegotiationAgentBuilderTurn() 함수 "advisor"가 분쟁 advisor와 혼동됨. 어떤 레이어의 어떤 동작인지 완전히 명시.
AdvisorMemory → NegotiationAgentBuilderMemory 타입 Negotiation Agent Builder Chat이 매 턴마다 누적하는 메모리 구조체임을 명시.
advisor-demo-types.ts → negotiation-agent-builder-types.ts 파일 파일명이 속한 레이어와 역할을 반영하도록.
intelligence-demo-api.ts (클라이언트) → negotiation-agent-builder-api.ts 파일 어느 레이어의 어떤 API 호출 파일인지 명확히.
/intelligence/demo/advisor-turn → /negotiation-agents/builder/chat-turn 라우트 Negotiation Agent 네임스페이스로. "demo" / "intelligence" / "advisor" 전부 제거. "chat-turn"으로 1회 채팅 턴임을 명시.
lumen-persona-profiles.ts → negotiation-agent-voice-profiles.ts 파일 "Lumen"은 내부 코드명. Negotiation Agent Builder Chat에서 AI 말투를 결정하는 보이스 프로필 파일임을 명시.
getAgentVoiceProfile() → getNegotiationAgentVoiceProfile() 함수 어떤 에이전트의 보이스 프로필인지 명시.
레이어 C — 협상 엔진 · 세션 (Negotiation Engine)
현재제안종류이유
engine-core (패키지) → negotiation-engine-core 패키지 "engine"만으로는 어떤 엔진인지 불명확. 협상 엔진임을 명시.
engine-session (패키지) → negotiation-engine-session 패키지 동상.
strategySnapshot (DB 컬럼, negotiation_sessions) → negotiation_agent_snapshot DB 컬럼 협상 시작 시 negotiation_agents에서 복사한 에이전트 설정값의 불변 스냅샷. "strategy"만으로는 무엇의 스냅샷인지 불명확.

아키텍처 결정 (2026-05-22): 옵션 A — 스냅샷 패턴 채택. negotiation_agents가 SOT, 협상 시작 시 값을 복사해 negotiation_agent_snapshot에 저장. 에이전트 수정이 진행 중인 협상에 영향을 주지 않으며, 분쟁 시 정확한 협상 값 재현 가능.
레이어 D — 분쟁 처리 (Dispute)
— 협상 에이전트와 완전히 별개
현재제안종류이유
advisor.ts → dispute-advisor.ts 파일 에이전트 빌더 채팅의 "advisor"와 혼동 방지. "분쟁" 명시.
레이어 E — 유저 장기 메모리 (Intelligence)
— 협상 에이전트와 직접 연결 없음, 변경 불필요
현재제안종류이유
intelligence.ts → intelligence.ts (유지) 파일 유저 장기 메모리 전용. 네임스페이스 잘 구분돼있음.
user_memory_cards → user_memory_cards (유지) DB 테이블 역할이 명확함. 변경 불필요.
4Demo 코드 규칙

규칙: Demo 코드는 프로덕션에서 직접 사용하지 않는다

demo 폴더 혹은 -demo가 붙은 파일은 레퍼런스 전용입니다. 동일한 기능이 잘 동작한다 하더라도, 프로덕션 코드는 반드시 별도로 구현합니다.

현재 이 규칙을 위반하고 있는 사례:

  • intelligence-demo.ts의 /intelligence/demo/advisor-turn → 프로덕션 buyer/seller 화면에서 직접 호출 중. 프로덕션 라우트 /agents/builder/turn 별도 구현 필요.
  • strategy-chat.tsx가 skipAuth: true로 demo 엔드포인트 호출 → 인증 유저도 동일한 demo 라우트를 탐.
5필드 이름 · 단위 불일치 — 엔진 연결 시 변환 필요

주의: 에이전트 빌더 채팅 출력값과 협상 엔진 입력값 사이에 필드 이름과 단위가 다릅니다. 그대로 연결하면 엔진이 엉뚱한 값으로 협상합니다. 반드시 변환 레이어가 필요합니다.

NegotiationAgentBuilderMemory 필드 단위 → 엔진 필드 (negotiation_agent_snapshot) 단위 현황
budgetMax USD 달러 → p_limit 센트 (×100) 변환 없음
targetPrice USD 달러 → p_target 센트 (×100) 변환 없음
negotiationStyle defensive/balanced/aggressive → (매핑 미정) — 설계 필요
riskStyle safe_first/balanced/lowest_price → (매핑 미정) — 설계 필요
mustHave / avoid string[] → (엔진 미사용) — 연결 안됨
6아키텍처 결정 기록 (ADR)
ADR-001 · negotiation_agent_snapshot 패턴
확정 · 2026-05-22
결정: 협상 세션의 에이전트 값은 스냅샷 패턴(옵션 A)으로 관리한다.
SOT: negotiation_agents 테이블이 에이전트 설정값의 단일 원본.
복사 시점: "Start Negotiation" 클릭 시, negotiation_agents 값을 negotiation_sessions.negotiation_agent_snapshot에 복사.
불변성: 협상 시작 이후 에이전트를 수정해도 진행 중인 협상에 영향 없음.
재현 가능: 분쟁 발생 시 해당 협상에서 정확히 어떤 값을 사용했는지 추적 가능.
기각된 옵션: 옵션 B(참조만) — 에이전트 수정이 진행 중 협상에 영향, 재현 불가. 옵션 C(Hybrid) — 과도한 복잡도.
ADR-002 · 익명 유저 에이전트 저장 전략
확정 · 2026-05-22
결정: 익명 유저의 NegotiationAgentBuilderMemory는 localStorage 임시 보관 후, 회원가입 시 DB 저장.
플로우: 채팅 → localStorage 임시 보관 → 회원가입 없이도 협상 진행 가능 (세션 범위 한정) → 가입 완료 시 negotiation_agents에 사후 저장.
기각된 옵션: 옵션 A (회원가입 강제) — UX 마찰이 과도함.
