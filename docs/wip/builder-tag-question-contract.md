## 사용자 결과와 기준

2026-10-01 staging 매물 `dTJW3ejj` (`IPhone 15 Pro`, category `electronics`, tags
`["iphone-15-pro"]`)에서 예산 $850·목표 $680을 입력하면 채팅이 배터리 90/85/80%와
언락을 필수 질문으로 묶었다. 아래 Quick Setup은 같은 상품에 배터리 90/80/Any,
언락 Unlocked only/Any를 이미 제공하고 있었다.

기준은 [태그·스펙·few-shot 전체 흐름](../engine/tag-spec-fewshot.md)과
[criteria와 issues](../engine/criteria-and-issues.md)다. 태그는 리스팅에서 확정되고,
질문 층은 그 태그와 부모의 칸을 사용한다. HARD는 게이트, SOFT는 가격·선호의 레버다.
별도 아이폰 질문 표에서 배터리·언락을 HARD로 바꾸는 규칙은 이 기준과 어긋났다.

## 변경 흐름

1. 별도 아이폰 질문 표와 대화 내용으로 태그를 재추측하는 분기를 제거했다.
   서버 질문 계획도 공유 taxonomy의 `resolveChecks`로 리스팅 category/tags와 부모를 읽는다.
2. 화면·서버가 같은 check ID, 구매자 질문, 선택지, HARD/SOFT를 사용한다.
   아이폰은 IMEI·할부 완납·침수·Find My가 HARD, 작동·외관·배터리·언락·용량이 SOFT다.
3. 선택지가 있는 칸은 채팅에서 재질문하지 않는다. 서버의 `quick_setup_check_id`로
   예산 제출과 일반 메시지 응답 모두 해당 Quick Setup 질문을 표시한다.
4. 답을 선택하면 모델 호출 없이 check ID에 stance/requirement를 저장한다. 서버는 이전
   선택을 먼저 합친 뒤 남은 질문을 판단하므로 모델이 답을 생략해도 다시 묻지 않는다.
5. 판매자가 필수로 지정한 선택형 칸도 같은 UI로 안내한다. 이미 선택한 칸과 완료된
   선택지를 모델이 임의로 다시 묻는 응답은 제거한다. 선택지가 없는 부모 칸은 정확한
   taxonomy 질문을 사용한다.
6. 상품 변경 시 조건 재사용, 모호한 답, 잠정적인 기준 변경의 재확인은 유지한다.
   배터리·언락의 SOFT 상태에서도 실제로 묻던 칸에 답을 연결한다.
7. 협상 missing-info의 배터리·언락 질문은 구매자 선호 대신 같은 check의 사실 질문과
   판매자 답 선택지를 사용한다. 개발자 데모도 check ID 답을 유지하고 같은 분류를 쓴다.

## 위험과 보호

질문이 표시됐다는 이유만으로 선택형 HARD 게이트를 완료 처리하지 않는다. 명시적인 stance나
기존의 해당 조건 증거가 필요하다. 새 태그·게이트를 모델이 만들지 않도록 기존 scaffold와
reconcile 규칙을 유지한다. 선택을 기록할 때 taxonomy HARD를 required로 고정하는 기존
안전 규칙과 협상 런타임의 PAUSE 규칙은 변경하지 않았다.

공유 taxonomy는 현재 구현된 질문 층이다. **Tag Garden DB DAG가 전체 시스템의 유일한
질문 나무가 되는 작업까지 완료했다고 주장하지 않는다.** 이 남은 범위는 기준 문서의
‘아직 없는 것’에 유지한다. 새로운 질문·임의의 85% 선택지는 추가하지 않았다.
