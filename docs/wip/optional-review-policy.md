# 리뷰어 선택 사항 전환과 staging 확인 대기

- 작업: `W2026-08-22-02`의 staging 통합 정책 slice
- 담당: 정행 (`jeonghaeng`), 기존 배정 유지
- 근거: 2026-10-01 사용자가 “리뷰어는 이제 필수가 아니야 그걸 수정해줘”라고 명시했다.
- 배포 상태: 사용자와 질문 답변 흐름 확인 전에는 staging에 병합·배포하지 않는다.

## 사용자 결과

리뷰어가 없거나 `proposed`라는 이유로 구현·완료·staging 배포가 막히지 않는다. 기존 리뷰어와
판단 기록은 보존하고, 필요하면 담당자와 다른 한 명에게 선택적으로 리뷰를 요청한다.

AGENTS·CONTRIBUTING·작업 그래프 운영 문서·PR/작업 카드 양식·작업 조회 검사를 같은 규칙으로
맞춘다. 동일 SHA의 최종 CI, 사용자에게 명시적으로 요청받은 배포 전 확인, main/production·공유
DB migration·live provider·실제 가치 자산·스마트 계약의 명시적 승인 조건은 유지한다.

이 정책은 이전 PR #200(응답 오류 복구)와 #201(태그 질문/Quick Setup 일치)의 ‘인오 리뷰어
확정·승인 대기’ 조건을 대체한다. PR 설명의 과거 상태는 실제 배포 준비 시 새 정책으로 갱신한다.
두 PR의 구현·검증 기록이나 기존 리뷰어 배정은 삭제하지 않는다.

## 에이전트와 태그 질문 답변 시점

재사용 에이전트는 상품을 연결하기 전 협상 성향을 설정한다. 구체적인 상품이 연결되면 해당
category/tags와 부모가 질문을 연다. 각 질문의 선택지 하나를 고르면 즉시 check ID에 답이
저장되고 다음 질문으로 이동한다. 필수 질문은 모두 답하고 선호 항목은 선택적으로 답한다.

- 판매자: 매물 등록의 5단계 Agent에서 상품 사실을 답한다. 태그가 연 HARD 미답이 있으면
  발행할 수 없다. 답은 draft/발행의 에이전트 전략 snapshot에 실린다.
- 구매자: 매물의 에이전트 선택·설정 패널 Quick Setup에서 구매 조건을 답하고 협상을 시작한다.
  선택한 답은 현재 설정과 브라우저 세션에 저장되며 협상 시작 요청에 전달된다. 재사용
  에이전트 자체를 저장하는 경우에는 저장된 에이전트 메모리에도 반영된다. 저장된 에이전트의
  대화는 500ms 지연 후 서버에도 동기화된다.
- 협상 중 추가로 필요한 필수 정보가 생기면 기존 런타임 PAUSE/추가 응답 경로를 사용한다.

사용자와 이 흐름을 확인한 뒤 정책 PR과 #200/#201을 staging에 통합한다. 현재 질문 시점 변경을
추가로 요청한 것으로 해석하여 제품 코드를 임의로 바꾸지 않는다.

## 검증과 남은 조건

선택적 리뷰어 검사의 회귀 테스트는 reviewer null/생략/not_assigned/proposed, 리뷰어 없이 done,
잘못된 reviewer 참조·자기 리뷰, 담당자 누락·의존성 누락을 확인한다. CI 품질 작업에도 연결한다.

기존 주간 그래프에서 리뷰어 미지정으로 막히던 W2026-08-31-01 검사는 통과한다. 전체 조회는
이어진 기존 HAGA-88의 `paperclip-engineer-1` 담당자 참조가 people에 없어 실패한다. 사용자나
다른 에이전트를 임의 배정하지 않고 이 별도 데이터 문제는 보존한다. 리뷰어 선택 사항 전환을
이유로 담당자·의존성 검사까지 무효화하지 않는다.

남은 조건은 사용자 흐름 확인과 각 최종 SHA의 CI다. 리뷰어 승인은 선택 사항이다.

로컬 회귀 테스트 7개, 변경 코드 Biome 및 diff 검사가 통과했다. staging의 유효 GitHub 규칙에는
삭제·non-fast-forward 방지만 있으며 필수 리뷰 승인은 없다. GitHub 저장소 설정 변경은 필요하지
않다. 정책 테스트는 CI 품질 작업에서도 실행한다.
