협상 엔진 — SOT

이 페이지 하나로 협상 엔진의 이상적 목표 설계(SOT)와 현재 실제 구현(현황)을 능력 단위로 나란히 봅니다. 모든 개발자·AI 툴이 "무엇이 목표이고 / 지금 어디까지 됐고 / 뭐가 known issue인지"를 여기서 확실히 파악합니다.

00 · Goals

목표 & 비전

AI 에이전트가 사람 대신 가격을 협상하도록 만드는 계산·의사결정 코어. 목표가·마지노선·성향을 설정하면 에이전트가 라운드를 주고받으며 양쪽에 공정한 합의점을 찾습니다.

결정론

동일 입력 → 동일 출력. 난수 없음.

역할 대칭

구매/판매 수식 동일, 파라미터 방향만 반대.

양쪽 공정

실제 BATNA만 사용, 허위 압력 금지.

현황 총평
결정론·역할대칭은 engine-core에서 지켜지나 그 레이어가 프로덕션에서 우회됨. 실제 결정은 LLM. → §1

01 · Architecture

아키텍처

실행 파이프라인✅ 경로 / 🚧 역할
이상형 · SOT

4계층(L0 Gateway · L1 Skill · L2 Engine · L3 Wire+Data). 매 라운드 6-Stage, LLM이 Understand·Decide 담당, 엔진이 Validate에서 검증. "LLM은 협상가, 엔진은 심판".

현황

프로덕션 라운드는 단일 경로로 수렴:

POST /negotiations/… · MCP haggle_submit_offer → getExecutor() lib/executor-factory.ts → executeStagedNegotiationRound pipeline/executor.ts (DB 트랜잭션) └ executePipeline → decide → LLM(grok)이 최종 가격 작성

✅ 6-Stage 실제 가동(유일 경로). Stage 1 Understand는 설계상 LLM이나 현재 정규식/휴리스틱 → 라운드당 LLM 콜 최대 1회(Decide).

현황 · known issue: 엔진 우회

engine-core computeUtility/makeDecision과 engine-session executeRound는 데모·테스트 전용. 프로덕션 라우트가 호출 안 함(executor-factory.ts 주석 명시). 단 가격 함수 computeCounterOffer는 코치가 import해 씀 — "엔진의 의사결정이 죽음"이 정확.

할 일

엔진 코어를 권위 advisory로 결정 경로에 재연결할지 결정 (§11-1).

03 · State machine

상태 머신 — 두 개의 독립 축 ✅

(a) phase — 협상 국면 (5)

DISCOVERY (건너뜀) → OPENING → BARGAINING → CLOSING → SETTLEMENT (종단) 역행: REVERT_REQUESTED · ABORT→SETTLEMENT

phase/phase-machine.ts

(b) status — 생명주기 (11)

REJECT→REJECTED · ACCEPT→ACCEPTED OPENING→ACTIVE BARGAINING: HOLD→WAITING / noConcession≥4→STALLED / else ACTIVE CLOSING→NEAR_DEAL

phase = "어느 단계냐", status = "살아있냐/멈췄냐/끝났냐". 🚧 DISCOVERY 우회 · ❓ NEGOTIATING_VERSION/FAILED_COMPATIBILITY 사용처 미확인.

(A) POST /negotiations/start — AI-vs-AI 자동재생

buyer-landing 실제 흐름. 구매자·판매자 양쪽 스냅샷을 컴파일(:1018·1038)하고, for(i<AUTO_PLAY_MAX_ROUNDS) 루프(:1099)에서 setSessionPerspective로 역할·스냅샷을 교체하며 executor를 번갈아 호출 — 협상 전체를 한 요청에서 서버가 자동으로 끝까지 재생. 양쪽 다 Haggle AI, 사람은 라운드마다 개입 안 함.

Stage 4 — Referee🚧
이상형 · SOT

7규칙(V1~V3 HARD, V4~V7 SOFT) + auto-fix로 LLM 결정을 거르는 안전장치.

현황 상세: reference/referee.md

✅ 7규칙 가동. V1 가격 floor 초과→floor · V2 phase 미허용 action→allowed[0] · V3 라운드소진 COUNTER→REJECT. V4~V7(역전·정체·일방양보·양보폭과다)는 SOFT, auto-fix 없음.

⚠️ HARD도 실제로는 차단 안 됨 — auto-fix MAX_RETRY=2 후 위반 남아도 통과. 'BLOCK'은 감사 라벨일 뿐.

⚠️ "가격 lock" 없음 — respond에 clamp/lock 전무. 유일 개입은 V1 floor 덮어쓰기(soft). 💀 ViolationTracker 미사용 → 항상 full 모드.

06 · The math

협상의 수학

6.2 Faratin 양보 곡선✅ 가격 결정
이상형 · SOT

P(t) = P_start + (P_limit − P_start) × (t/T)^(1/β). β<1 Boulware(막판 양보)·β>1 Conceder(초반 양보). 확장: 효용공간 역산·동적 β·AC_next.

현황

✅ price-space computeCounterOffer 가동(engine-core/decision/faratin.ts), 코치·룰이 β와 사용.

🚧 t는 실경과시간 아닌 time_pressure || round/max_rounds 근사. 💀 효용공간·동적 β·AC_next·후반완화 미구현(β 고정).

6.1 효용 U_total🚧 advisory
이상형 · SOT

U_total = w_p·V_p + w_t·V_t + w_r·V_r + w_s·V_s. V_p는 로그(한계효용 체감), V_s_base=0.5로 초면 중립.

현황

engine-core에 정확 구현되나 프로덕션 미사용. 코치는 단순화·하드코딩 u_total만, 그마저 프롬프트 미도달.

할 일

07 · Tactics

의사결정 전술

결정 규칙 + 전술🚧 LLM이 결정
이상형 · SOT

우선순위 규칙: ESCALATE(처리불가) → ACCEPT(u≥aspiration) → NEAR_DEAL(u≥threshold) → COUNTER(u>0) → REJECT(u≤0) → ESCALATE(교착 noConcession≥4). 전술 엔진: 미러링, 상대패턴×단계 매트릭스.

현황

🚧 위 규칙은 engine-core makeDecision(비활성)에 있음. 프로덕션 ACCEPT/REJECT는 LLM + gap 휴리스틱. 코치가 suggested_tactic(nibble/anchoring 등) 파생해 프롬프트 전달하나 강제력 없음. 전술 매트릭스·미러링 미구현.

08 · LLM

LLM 통합

현황 ✅
💀 "라운드당 2회"는 틀림 → 실제 1회(Decide만). Respond는 템플릿(LLM 미호출), pipeline respond 토큰 합산은 죽은 코드. · ✅ xAI 고정(XAI_MODEL, 기본 grok-4-fast), reasoning은 fast 모델엔 미적용. · ✅ 토큰 실측 → negotiation_rounds.llm_tokens_used 저장. · 🚧 비용 러프 추정·DB 미저장(tokens/1000×0.0015, 정확요금은 advisor 모듈에만). · 💀 세션당 비용 집계 없음("~$0.005/세션"은 데모값).

09 · Topology

토폴로지 & 크로스프레셔

1:N 병렬 협상💀 dormant
이상형 · SOT

batchEvaluate로 Top N 세션, 나머지 WAITING. 한 세션 ACCEPTED 시 나머지 SUPERSEDED. 크로스프레셔는 BATNA만 주입(허위 금지, 세션당 ≤2회, 차이<5%면 미주입). N:1 Anti-Sniping.

현황 — 완성돼 있으나 도달 불가

서브시스템(엔진·DB·전용 라우트)은 배선됐으나 프로덕션 /negotiations/start가 그룹을 생성 안 함(createSession groupId 없이, negotiations.ts:1079). 그룹은 수동 POST /negotiations/groups로만, 웹앱 미호출.

💀 batchEvaluate 프로덕션 호출자 0 · 💀 크로스프레셔/BATNA dead branch(memory.competition 미설정, L5가 competition 미반환 "Not implemented in Phase 0") · 🚧 supersede는 if(session.groupId) 뒤 · 💀 Anti-Sniping 코드 없음.
