- 모델이 가격을 판단. 코드는 **클립만**. HARD 실패 → ACCEPT 금지.
- 하지 않은 것: 용량 고정 타결표, 카테고리 `$50-80/tier`, Faratin으로 타임아웃 채움, `if (category === "phone")`.

### Decide 모델

- 카테고리·구매자 목표가 아니라 **공개 호가**. `$100` 미만 Flash, 그 위/호가 미상 Pro.
- 카탈로그에서 **모델 id**를 고름. cheap/default 티어 이름 없음.
- 구매자 턴 / 판매자 턴이 **각자** 부를 수 있음.
- 시작 JSON의 `pro_model_credit`는 라우팅에 안 씀. 클라이언트 플래그 스트립.

### 수수료

- 우리 요금 **1.5%만**. 달러 하한·피크 할증 없음.
- 카드 온램프 **1.5%** 추가(구매자). 코드에서 `+$0.30`은 0으로 고정.
- `+$0.30`은 Stripe 원가 메모였지 우리 청구가 아님.

### 크레딧 (장부 없음)

- `negotiation-credit-policy.ts`에 견적·출석 식만. 지갑·차감 없음.

### 홀드 (W22-09)

## 2. 오늘 숫자로 말할 손익 (필요 성사율)

한 판이 이득이려면: **결제 확률 > 원가 / 수수료**.
가정: 4라운드×양쪽, off-peak, Flash ≈ $0.017 / Pro ≈ $0.052, 수수료 1.5%.

| 호가 | 모델 | 필요 성사율 |
|------|------|-------------|
| $20 | Flash | 5.8% |
| $80 | Flash | 1.4% |
| $99 | Flash | 1.2% |
| **$100** | **Pro** | **3.5% (점프)** |
| $200 | Pro | 1.7% |
| $500 | Pro | 0.7% |

말할 포인트:

- $80–$200은 대략 **1.4–1.7%**면 LLM은 이긴다. 부족한 건 원가가 아니라 **결제 없이 판만 도는 것**.
- `$100`에서 필요 성사율이 세 배가 된다. 수수료는 1%만 늘고 원가는 3배.
- 피크면 위 숫자 **2배**.
- 같은 매물에 판을 n개 열면 결제는 한 번. `결제÷세션`이 위 퍼센트보다 커야 한다. $200은 **58판**을 넘으면 매물이 항상 팔려도 적자.
- 호가 $150 + 최저가 $100이면, **성사되면** $100–$150. 무조건 성사는 아님. 구매자 예산이 $100 아래면 거절.

수평으로 맞추려면 (초안, 미구현): 세션 AI 예산을 호가에 비례. 싼 매물 Flash+짧은 대화, 비싼 매물 Pro. `$100` if문 대신 예산으로 id 고르기.

## 3. 오늘 결정할 것 (초안 → 합의만)

상세 표는 8/28 문서. 여기서는 질문만.

1. **판매자 좋은 모델** — 기본($100+면 양쪽 Pro)은 우리 원가. 기본보다 올릴 때만 판매자 크레딧? 지금은 기본만?
2. **가입 200 / 출석 10→20 / 결제·정산·초대 보너스** 쓸지. 출석=매일 1판은 이미 버림.
3. **홀드 틱을 결제에만** 걸지, P 수명 2시간이 짧은지, 홀드가를 화면에 보여줄지(지금은 숨김).
4. **`W2026-08-22-05` 담당·리뷰어** — 장부는 견적 함수에 붙이면 됨. 담당 없으면 프로덕션 크레딧 못 켬.
5. **카드 1.5% 고지**를 시작 화면에서 더 세게 할지.

합의된 뒤에만 SOT·지급표·홀드 숫자를 고정한다.

## 4. 다음 제품 (결정 아님, 방향만 공유)

그록처럼 **목표 + 크레딧**을 넣으면 에이전트가 매물을 고르고 판을 여는 그림.

- 비슷한 매물일 때만 자동 시작. 평가는 기존 유사 점수 + 필수 칸. 핫 패스에 LLM 채점 넣지 말 것.
- 알림과 자동은 **같은 평가, 다른 문턱**. 알림만으로 컷을 맞춘 뒤 자동.
- 이득은 시도 수가 아니라 **안 팔릴 뻔한 매물이 맞는 구매자를 만나는 것**. 매물당 자동 2명 다음엔 낭비.
- 지금 자동은 브라우저가 `/auto-play/next`를 한 라운드씩. 탭 닫으면 끊김. 서버 워커·1:N은 없음.

이건 새 카드. 오늘 구현 범위 아님.
