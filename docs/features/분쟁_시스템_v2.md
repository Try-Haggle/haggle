# 분쟁 시스템 v2

> 이 문서는 Haggle 분쟁 해결 시스템의 설계 전문입니다.
> v8.3 분쟁 비용 구조를 대체합니다.

**구현 상태 (2026-09-26):** 분쟁 생성·증거·AI·정산 및 리뷰어 API가 구현되어 있다. T2/T3 단계별 배정·투표·승급 화면 연결을 보완했으며, 공유 DB migration·staging 검증·리뷰 승인은 남아 있다. 상세 현황과 설계 대비 미구현 항목은 [T2/T3 작업 카드](../wip/dispute-tier-review-implementation.md)를 따른다.
**패키지:** `packages/dispute-core/`

**정산 정책 확정 (2026-09-27):** 최종 승소자의 분쟁 비용은 $0이다. 구매대금과 별도로 구매자·판매자가 각각 심사비 보증금을 스마트 컨트랙트에 예치한다. 최종 패소자의 보증금에서 심사비를 정산하고 승소자의 보증금은 전액 반환하며, 승소자의 대금·환불금에서 분쟁 비용을 공제하지 않는다. 아래 6·7절은 목표 설계이고 임시 코드의 동작이나 구현 완료를 뜻하지 않는다.

**크레딧 후속 합의 (2026-09-27):** 크레딧은 한 종류·합산 잔액으로 표시하고 내부에서 구매분/보상분의 출처를 추적한다. 분쟁 승소 시 보류한 원래 발생분과 수량을 복원한다. 아래 USDC 직접 예치와 크레딧 사용을 연결하는 재원·계약 구조, 유료 판매 개시·환산율·할증은 아직 확정하지 않았다. [합의 및 법적 검토](../wip/dispute-credit-legal-review.md)를 따른다. 다수파 보수·패소자 전액 부담·미예치 종료의 법적 집행 가능성도 실자금 출시 전 검토 대상이다.

**단계 요금 결정 (2026-10-01):** 정행은 실제 실시한 T2·T3 비용을 합산하기로 했다. 예를 들어 T2 $12와 T3 $30을 모두 심사하면 최종 패소자의 비용은 $42다. 이번 구현에서 리뷰어 실제 보수 지급은 보류하고, 양측 별도 예치·심사 개시·최종 정산의 기반만 연결한다. 사건별 보수 동의와 대체 절차, 실자금 출시는 별도 결정으로 남긴다.

**참여 보증금 구체화 (2026-09-27):** [자기 이용료·예치·최종 환급 상세 초안](../wip/dispute-deposit-settlement-design.md)에 견적 고정, 양측 확보 후 배정, 재심 중 담보 보존, 자산별 반환과 중복 정산 방지를 기록했다. 각자의 자기 이용료 면제/정산 구조, 단계별 누적안, 크레딧 사용 시 회사 USDC 담보안은 권고 초안이다. 다수파 USDC·소수파 크레딧 제안은 결과 연동 문제를 해결한 것으로 채택하지 않았다.

**익명 심사·유타법 검토 추가 (2026-09-29):** 사용자 설명에 따른 유타 회사·당사자 신원 비공개 심사를 전제로, 다수파 보수안을 유지할 합의 근거와 선택형 중재 권고를 [4절](#anonymous-utah-review)에 추가했다. 문서화한 법적 분석·권고이며, 선택형/필수 절차의 최종 정책 결정이나 법률·실자금 출시 승인을 뜻하지 않는다. 필요한 인허가는 취득한다는 운영 전제이며 이미 취득했다는 증거는 아니다.

## 2. 3-Tier 구조

### 비용 공식

```
Tier 1:  max(거래액 × 0.5%, $3)    — AI 판사 (단독)
Tier 2:  max(거래액 × 2%,  $12)    — 배심원 재판 (Panel)
Tier 3:  max(거래액 × 5%,  $30)    — 배심원 대재판 (Grand Panel)
```

### 에스컬레이션 배수

| 구간 | 배수 | 의미 |
|------|------|------|
| T1 → T2 | **4x** | AI 결과 불복 시 상당한 비용 증가 |
| T2 → T3 | **2.5x** | 패널 결과 불복 시 추가 비용 |

### 전환점

$600 이하: 최소 비용 적용 ($3 / $12 / $30)
$600 이상: 비율 적용 (0.5% / 2% / 5%)
→ 3개 Tier 전환점이 모두 $600으로 일치

### 비용 테이블

| 거래액 | Tier 1 | Tier 2 | Tier 3 |
|-------|--------|--------|--------|
| $50 | $3 | $12 | $30 |
| $100 | $3 | $12 | $30 |
| $500 | $3 | $12 | $30 |
| $1K | $5 | $20 | $50 |
| $5K | $25 | $100 | $250 |

## 3. 법원 비유: 배심원 재판 모델

### 역할 구조

```
실제 법원              →    해글 분쟁
──────────                  ──────────
원고측 변호사           →    구매자측 AI
피고측 변호사           →    판매자측 AI
판사                   →    T1: AI 단독 판결
배심원                 →    T2/T3: 일반 사용자 다수결
전문가 증인            →    Skill (외부 API, 예: skill-legit)
```

### 왜 배심원 모델인가

- 전문 리뷰어 모집은 비현실적 (스케일 불가)
- 일반 사용자도 **AI가 쟁점을 정리해주면** 충분히 판단 가능
- 전문성이 필요한 경우 → Skill로 외부 전문가 API 호출 (증거로 활용)

### 배심원 자격

```
거래 5건 이상 완료 AND Trust Score 50 이상 AND 퀄리파이 테스트 70% 이상
```

별도 모집, 훈련 불필요. 기존 사용자가 퀄리파이 테스트를 통과하면 배심원.

### 퀄리파이 테스트 (Qualification Test)

판례 DB 기반 시뮬레이션 시험. 배심원의 판단력을 사전 검증하고, 기존 판례와의 일관성을 확보한다.

**방식:**

```
1. 시스템이 완료된 분쟁 케이스 10개를 랜덤 제시
2. 응시자가 쟁점 요약을 읽고 투표 (실제 배심원 화면과 동일)
3. 실제 다수파 결과와 비교
4. 60% 이상 일치 → 자격 부여
```

**설계 원칙:**

| 원칙 | 적용 |
|------|------|
| 공정함 | 경제적 조건(스테이킹) 아닌 판단력으로 자격 부여 |
| 투명함 | 합격/불합격 기준 명확 (70% 일치율) |
| 교육 효과 | 테스트 자체가 판례 학습 — "배터리 13% 차이는 환불 사유" 등 자연 학습 |
| 일관성 | 신규 배심원이 기존 판례 기준과 정렬된 상태에서 시작 |

**합격 기준:**

| 점수 | 결과 | 다음 단계 |
|------|------|----------|
| 70% 이상 | 즉시 합격 | 배심원 자격 즉시 부여 |
| 60% ~ 70% 미만 | 조건부 | 추가 트레이닝 모듈 이수 후 자격 부여 |
| 60% 미만 | 불합격 | 24시간 후 재응시 가능 |

**추가 트레이닝 모듈 (60% 미만 시):**

- 오답 케이스의 실제 판례 결과 + 판단 근거를 제시
- "왜 이 결과가 나왔는가"를 학습한 후 새 케이스 세트로 재시험
- 트레이닝 자체가 판례 학습 기회 — 배심원 풀 확대 목적

**재시험 규칙:**

- 케이스 세트는 매번 랜덤 추출 (암기 방지)
- 응시 횟수 제한 없음 — 배심원 풀 최대화 우선

**스테이킹:**

스테이킹은 자격 조건이 아님. 이미 3중 페널티 구조(DS 점수 하락 + 보상 $0 + 등급 하락)가 오판 억제에 충분.
초반 배심원 보상이 낮은 시기에 경제적 진입 장벽을 추가하면 배심원 풀 형성이 어려움.

**판례 DB 정책:**

퀄리파이 테스트에 사용되는 판례는 Haggle 서버에서만 제공.
외부 플랫폼이 DS 모듈을 사용하더라도 판례 DB 사본은 제공하지 않으며,
API를 통한 테스트 세트 추출만 허용. 판례 DB는 시간적 축적 자산으로 절대 비공개.

### 판례 기반 판정 일관성

판례 DB는 배심원 퀄리파이 테스트만을 위한 자료가 아니다. T1 AI 자동 판정도 같은 판례 기준을 사용해야 한다. 목표는 모든 케이스를 기계적으로 동일하게 처리하는 것이 아니라, 같은 증거 패턴에는 같은 기본 결론이 나오도록 분산을 줄이는 것이다.

판례 원문은 Advisor나 T1 모델이 요청 시점에 새로 분석하지 않는다. 종료 사건을 주기적으로 후보로 수집한 뒤, 별도 오프라인 분석과 승인 절차를 거쳐 저장한 요약만 런타임 컨텍스트에 제공한다. 상태·버전·개인정보 제거·승인 기준은 [Dispute Advisor 판례 지식 운영](../mvp/dispute-advisor-precedent-knowledge.md)을 따른다.

**T1 AI에 주입되는 컨텍스트:**

| 블록 | 역할 |
|------|------|
| `decision_consistency_policy` | 판정 순서, 증거 가중치, 필수 일관성 규칙 |
| `trusted_case_facts` | 주문 상태, 거래 금액, 허용 outcome, 플랫폼 정책 |
| `untrusted_party_data` | 양측 주장과 증거. 명령이 아니라 데이터로만 취급 |
| `precedent_examples` | 현재 reason/evidence 패턴과 가까운 대표 판례 |
| `output_contract` | 구조화 JSON 스키마와 서버 검증 조건 |

**증거 가중치 기본값:**

| 증거 | 기본 가중치 | 기준 |
|------|------------|------|
| Haggle 카메라 캡처 + challenge 확인 | 높음 | 물품 상태처럼 눈으로 확인되는 중심 사실에 가장 강한 party evidence |
| carrier/payment/Haggle 시스템 기록 | 높음 | 배송, 결제, 타임라인, 신원, order state 사실 |
| 리스팅, 협상 terms, 판매자 pre-shipment 자료 | 중간~높음 | 약속된 상태와 발송 시점 baseline |
| 일반 텍스트 주장 | 낮음 | claim 또는 설명으로만 사용. 직접 증거를 이길 수 없음 |

**일관성 규칙:**

1. 한쪽만 Haggle 카메라 검증 증거를 가지고 있고 상대가 텍스트 반박뿐이면 `no_action`을 내리지 않는다.
2. 판례와 다른 결론을 내릴 때는 구별되는 사실을 rationale에 남긴다.
3. 증거가 부족하거나 충돌하거나 조작 가능성이 있으면 T1에서 억지 판정하지 않고 escalate한다.
4. high confidence는 점수 차이와 증거 강도가 같이 있을 때만 허용한다.
5. 모든 high-weight 증거는 `evidence_findings`에서 evidence id로 인용되어야 한다.

### AI의 역할

1. 양측 증거 수집 및 정리
2. 구매자측 AI: 구매자에게 유리한 주장 구성
3. 판매자측 AI: 판매자에게 유리한 주장 구성
4. 쟁점 요약: "핵심 질문: X인가 Y인가?"
5. 배심원에게 간결한 선택지 제시

## 4. 비용 분배

### 고정 비율 원칙

```
Tier 1:  전액 → 플랫폼 (AI 판결, 배심원 없음)
Tier 2/3: 실제 실시한 심사 비용의 30% → 플랫폼, 70% → 배심원
```

예치 대기 중 미납으로 종료되어 실시하지 않은 단계는 심사비·플랫폼 배분·배심원 보상 모두 $0이다.
이 예외로 이전 단계에서 이미 발생한 심사 보수까지 소멸시키지 않는다. 상세 조건은 6·7절을 따른다.

왜 고정 비율인가:
- **투명**: "70%는 배심원, 30%는 플랫폼" — 한 문장으로 설명 가능
- **공정**: 거래액, 투표 결과와 무관하게 항상 동일 비율
- **예측 가능**: 배심원이 사전에 보상 계산 가능
- **모듈화 용이**: 다른 플랫폼은 비율만 변경

### 1인당 보상 계산

```
1인당 = (분쟁비용 × 70%) ÷ 다수파 수
```

|-------|---------|---------------|-------|-------|----------|
| $100 | $12 | $8.40 | 5 | 3 | **$2.80** |
| $500 | $12 | $8.40 | 5 | 3 | **$2.80** |
| $1K | $20 | $14.00 | 7 | 4 | **$3.50** |
| $3K | $60 | $42.00 | 9 | 5 | **$8.40** |
| $5K | $100 | $70.00 | 11 | 6 | **$11.67** |
| $10K | $200 | $140.00 | 11 | 6 | **$23.33** |
| $25K | $500 | $350.00 | 15 | 8 | **$43.75** |
| $50K | $1K | $700.00 | 21 | 11 | **$63.64** |
| $100K | $2K | $1,400.00 | 29 | 15 | **$93.33** |

### 다수파만 보상

**기존 설계·조건부 운영안 검토:** 아래 보수·DS 규칙의 실자금 채택은 확정하지 않았다. 아래 익명·대칭 보수와 유효한 당사자 합의를 결합한 유타 운영안에는 법적 근거가 있으며, 결과 연동이라는 이유만으로 일률 금지라고 판단하지 않는다. 다수파 USDC·소수파 크레딧으로 자산을 달리하는 것만으로 결과 연동 문제가 없어지지는 않는다. [후속 검토와 별도 보수 대안](../wip/dispute-deposit-settlement-design.md#6-다수파-usdc소수파-크레딧-보수안의-판단)을 참고한다.

- 다수 의견 배심원만 보상 수령
- 소수파 = $0
- 고등급 배심원이 소수파 → 가중 DS 감점 (vote_weight 비례)

### 익명 심사와 유타 선택형 중재 검토

**검토 판단:** 유타법이 유효하게 적용되고 아래 합의·절차 조건을 갖춘 사건에서는 다수파 보수를 유지할 실질적인 법적 근거가 있다. 익명성만으로 법적 중립성이 확정되는 것은 아니며, 동일한 해글 보수식을 승인한 판례를 확인한 것도 아니다. 회사 소재지·리뷰어 거주지만으로 준거법이나 중재지가 결정되지 않는다.

- **익명·대칭 보수:** 리뷰어에게 당사자 신원을 가리고, 구매자·판매자 중 어느 쪽이 승소하든 같은 산식을 적용한다는 전제다. 특정인을 편들 위험을 줄이지만 다수 판단과의 일치 여부에 따라 본인 보수가 달라지는 이해관계는 남는다. 익명화의 실제 구현·증거 내 식별정보 차단은 검증 대상이다.
- **합의의 법적 근거:** 유타 §78B-11-105는 §112의 이해관계 제한을 변경 불가능한 조항으로 열거하지 않는다. 그 원형인 RUAA §11 공식 해설은 당사자 합의로 해당 이해관계를 가진 사람도 중립 중재인으로 선택할 수 있다고 설명한다. 모범법 해설은 유타 법원의 직접 판결과 구분한다.
- **권고하는 동의 방식:** 분쟁 발생 후 양측에 지급 산식, 다수파만 보수 수령, 소수파 무보수·DS 감점, 비용 부담, 보수 확정 시점을 별도로 설명하고 해당 사건에 적용할 방식을 명시적으로 선택하게 한다. 사건별 동의는 위험 감소 권고이며 모든 유타 중재에 법이 일률적으로 요구하는 절차라는 뜻은 아니다.
- **선택권:** 선택형 운영안을 채택하면 거절 시 실제 이용 가능한 다른 해결 절차가 있어야 한다. 보수 방식에 동의하지 않았다는 이유만으로 자동 패소·보증금 몰수·자금 무기한 동결을 적용하지 않는다. 거절 후 대체 절차, 자금 보존·반환 기한과 비용은 후속 결정 대상이다.
- **독립 판단과 기록:** 다른 리뷰어의 선택이 공개되기 전에 투표·이유를 확정하고, 운영 단계의 이해충돌 확인·필요한 공개·기피, 증거 접근·반론 기회 및 합의 버전 기록을 갖추는 방향을 권고한다. 익명 심사가 이해충돌 확인·공개를 생략하는 근거는 아니다.
- **합의의 한계:** 동의 대상은 공개된 보수 조건이다. 숨겨진 이해관계·담합·뇌물·중요 증거 배제까지 면책하거나 법원의 판정 취소 심사를 포괄적으로 배제하지 않는다. §124의 취소 규정이 남는다는 사실이 §112에 관한 구체적인 합의 가능성까지 없애는 것은 아니다.
- **캘리포니아·해외:** California Standard 16이 적용되는 사건에는 결과 연동 보수의 명시적 금지가 있어 같은 합의 경로를 그대로 적용하지 않는다. 유타·해외 리뷰어만 뽑는 것으로 적용 제외가 확정되지 않으며, 해외 근무국별 의무와 USDC 보관·정산의 금융규제도 별도다.

**남은 제품 결정:** 이 보수 방식을 선택형으로 제공할지 필수 절차로 유지할지, 거절 시 대체 절차, T2/T3 동의 범위와 재심 시 이전 보수·DS 확정 규칙을 정한다. 이번 추가는 선택형 운영 권고를 SoT에 기록한 것이며 기존 비용 공식·30/70 배분·보수·DS를 코드에서 변경하지 않는다. T3 독립 패널 재심은 유지하고 모든 사건의 외부 재심을 새로 의무화하지 않는다.

근거와 판례의 한계: [유타 §105](https://le.utah.gov/xcode/Title78B/Chapter11/C78B-11-S105_1800010118000101.pdf), [RUAA 공식 원문·§11 해설 40–41쪽](https://www.uniformlaws.org/HigherLogic/System/DownloadDocumentFile.ashx?DocumentFileKey=cf35cea8-4434-0d6b-408d-756f961489af&forceDialog=0), [상세 법률 분석과 유·불리한 판례](../wip/dispute-credit-legal-review.md#utah-consent-review).

## 5. 배심원 배정

### 알고리즘: Efraimidis-Spirakis (ES)

```
각 배심원에게 key = random^(1/weight) 생성
→ 상위 N개 선택
→ seed = hash(dispute_id) (결정론적, 감사 가능)
```

성능: 50,000명 풀에서 45명 선택 < 5ms

### 배정 파이프라인

**선행 조건:** 구매대금과 별도로 양측의 해당 단계 심사비 보증금이 스마트 컨트랙트에 확보된 것을 확인한 뒤 배정을 시작한다.
예치 대기 중에는 배정·리뷰 요청·투표를 열지 않고 리뷰어 슬롯도 차지하지 않는다.
미납 종료와 배정 시작은 서로 배타적으로 처리한다.

```
1. Pre-filter
   - 슬롯 초과 → 제외
   - 이해충돌 → 제외 (거래 당사자 관련)
   - 배심원 자격 미달 → 제외

2. Idle-first (무조건 놀고 있는 사람 먼저)
   0건 처리 중인 사람만으로 풀 구성
     → 충분하면 (≥ N명) → 여기서 ES 선택 → 끝
     → 부족하면 → 1건 처리 중 추가 → 2건 → ...

3. Weight 기반 ES 선택
   weight = tierWeight × performanceBoost
```

### tierWeight

| 배심원 별 | 가중치 | ⭐ 대비 |
|---------|--------|-------|
| ⭐ (0-30점) | 1.0 | 1.0x |
| ⭐⭐ (31-50점) | 1.2 | 1.2x |
| ⭐⭐⭐ (51-70점) | 1.5 | 1.5x |
| ⭐⭐⭐⭐ (71-85점) | 1.8 | 1.8x |
| ⭐⭐⭐⭐⭐ (86+점) | 2.2 | 2.2x |

최대 격차 2.2배. **별 수가 배정 자격을 제한하지 않음** — 확률만 조절.
⭐ 배심원도 $100K 분쟁에 배정될 수 있음 (확률 낮을 뿐).

### performanceBoost

```
performanceBoost = 1.0
  + 0.2 × (zone_hit_rate - 0.5)       정확할수록 ↑
  + 0.1 × (1 - response_hours / 48)    빠를수록 ↑
  + 0.1 × min(completed_cases / 100, 1) 경험 많을수록 ↑
```

범위: ~0.8 ~ 1.4. 잘하는 사람 = 더 자주 뽑힘 (벌칙이 아닌 보상).

### 슬롯 시스템

전원 동일 한도: **3슬롯**. 등급 무관.

## 6. 심사비 보증금과 심사 시작 조건

보증금은 구매자·판매자 각자의 참여 담보다. 본인 이용료와 상대방 비용의 구분, 심사 이행 기록 및 최종 면제·정산 순서는 [상세 초안](../wip/dispute-deposit-settlement-design.md#2-보증금과-자기-이용료의-관계)을 따른다. 이 초안만으로 소비자 비용 규정의 적용 제외가 확정되는 것은 아니다.

### 승소자 무부담 원칙과 재원

- 구매대금은 거래 정산·환불 전용이다. 패소자가 구매자여도 여기서 심사비를 빼면 승소한 판매자의 수령액이 줄어들므로 공제하지 않는다.
- 판매자 보증금은 스마트 컨트랙트에 예치한다. 회사 운영 지갑으로 받는 임시 구현을 최종 구조로 삼지 않는다.
- **양측 별도 보증금:** T2/T3 심사 시작 전에 구매자·판매자가 각각 해당 단계 심사비 상당액을 스마트 컨트랙트에 예치한다. 구매자의 보증금은 기존 구매대금에 추가되는 금액이며, 구매대금을 보증금으로 중복 계산하지 않는다.
- 보증금은 선납 수익이 아니다. 최종 승소자의 보증금은 전액 반환하고, 최종 패소자의 보증금에서 실제 발생한 심사비만 정산한다. 미사용 잔액은 납부자에게 반환한다.
- 구매대금 $500, 심사비 $12라면 구매자는 기존 대금 $500에 더해 $12, 판매자는 $12를 예치한다. 구매자가 패소해도 판매대금 $500과 판매자 자기 보증금 $12를 모두 지급·반환하면서 구매자 보증금 $12로 심사비를 충당할 수 있다.
- 기존 단계 보수의 담보는 다음 단계 예치와 구분해 유지한다. T3에 진입한다고 이미 발생한 T2 보수의 재원을 환불하거나 새 단계 재원으로 중복 사용하지 않는다.

### 판매자 미예치 종료: 해당 단계의 리뷰 없음

**동의 거절과의 구분:** 아래는 기존 예치 의무 불이행의 목표 정책이다. [선택형 유타 운영안](#anonymous-utah-review)을 채택할 경우, 그 보수 방식에 동의하지 않은 사건을 아래 미납 종료로 우회 처리하지 않는다. 미동의·미응답과 유효하게 합의한 절차의 미납을 구분하는 규칙은 후속 설계 대상이다.

1. T2/T3 요청 후 예치 대기 상태에서 필요한 금액·기한·미납 결과를 양측에 안내한다. 판매자 기한은 T2 48시간, T3 72시간이다.
2. 양측 보증금이 확인되기 전에는 리뷰어를 배정하거나 심사 작업을 요청하지 않는다.
3. 구매대금과 구매자 보증금이 정상 예치되었으나 판매자가 기한 내 예치하지 않은 경우, 통지·입금 기록·기한을 확인한 뒤 **판매자 미예치 패소**로 종료한다. 패널의 본안 판단과 구분된 종료 사유를 기록한다.
4. 실시하지 않은 해당 단계의 심사비·리뷰어 보상·플랫폼 배분은 모두 **$0**이다. 이를 미수 수수료로 만들어 추후 청구하지 않는다. 구매대금과 구매자의 해당 단계 보증금도 전액 반환한다.
5. T2 패널 시작 전 종료라면 T2 리뷰어에게 줄 돈이 없는 것이 정상이다. T1 운영 비용이 이미 발생했더라도 미납 종료를 이유로 승소 구매자에게 전가하지 않으며, 확보되지 않은 비용은 플랫폼 부담이다.
6. T3 시작 전 미납 종료라면 **미실시 T3 비용만 $0**이다. 이미 실시한 T2의 보수와 담보는 유지하고, 최종 승패에 따른 부담·환급을 별도 정산한다.

**경계 조건:**

- 네트워크·서비스 장애, 입금 확인 지연, 기한 내 전송 여부가 불명확한 상태를 단순 미납으로 확정하지 않는다. 자금 확인 후 종료 또는 심사 시작 중 하나만 실행한다.
- 이미 리뷰어에게 작업을 맡긴 사건은 “미실시 심사” 예외로 보수를 지우지 않는다. 예외적으로 담보 부족 상태에서 작업을 요청했다면, 그로 인한 보상 부족분은 플랫폼이 책임지며 승소자에게 전가하지 않는다.
- 구매자 미납 또는 양측 미납이면 패널을 시작하지 않는다. 이 경우 요청 취소·기존 결과 유지 등 상세 정책은 별도 확정 대상으로 남기며, 판매자만 자동 패소시키는 규칙을 적용하지 않는다.
- 이 절은 제품·재원 설계다. 미납 종료 조항의 법적 집행 가능성까지 확정한 것은 아니다.

### 보증금 처리

| 종료 상태 | 승소자 | 패소자 | 해당 단계 심사비 |
|-----------|--------|--------|------------------|
| 실제 심사 후 최종 승패 확정 | 보증금 전액 반환 | 별도 보증금에서 실제 심사비 정산, 잔액 반환 | 기존 단계별 공식 |
| 패널 시작 전 판매자 미예치 종료 | 구매자의 해당 단계 보증금 전액 반환 | 해당 단계 미예치금 없음 | $0 |

### 단계 간 비용 정책의 남은 결정

기존 비용표만으로는 T1/T2/T3 비용을 누적 청구하는지, 최종 단계 금액이 이전 단계를 포함하는지가 확정되지 않는다.
이 수정에서 새 누적 요금을 임의로 확정하지 않는다. 다음 조건을 만족하는 견적·담보 규칙을 정한 뒤 실제 청구를 연결한다.

- 이미 실시한 단계의 보수와 새 단계 예상 비용을 각각 표시하고, 각 재원을 중복 계산하지 않는다.
- T3에서 결과가 뒤집혀도 최종 승소자에게 이전 단계 심사비가 남지 않는다. 최종 확정 전 승소 가능 당사자의 담보를 소진하지 않는다.
- 이전 단계 심사 보수의 재원 보존과 T3 번복 시 이전 다수파 보상·DS의 확정 방식은 구분한다. 후자의 소급 조정 여부는 별도 결정 대상이다.
- 이미 발생한 보수의 재원을 확보하고, 실시하지 않은 단계에는 요금을 부과하지 않는다.
- T1 유료 처리도 구매대금 공제로 우회하지 않는다. 별도 재원·승소자 환급이 확보되지 않은 비용은 승소자에게 청구하지 않는다.

## 7. 정산 (Settlement)

### 자금 흐름

**최종 승소자의 분쟁 비용은 $0이다.** 판매자 승소 시 판매대금 전액, 구매자 승소 시 구매대금 전액을 지급·환불하고 각자의 심사비 보증금도 전액 반환한다.
여기서 무부담은 분쟁 때문에 추가되는 비용을 뜻하며, 기존 거래 수수료·배송비 정책을 새로 변경하는 것은 아니다. 아래 표는 이 항목들을 제외한 분쟁 정산 원금을 기준으로 한다.

분쟁 비용 출처:
- **구매자 패소** → 구매대금과 분리된 구매자 심사비 보증금
- **판매자 패소** → 판매자 심사비 보증금
- **패널 시작 전 미예치 종료** → 실시하지 않은 단계는 비용 자체가 $0

분쟁 비용 행선지:
- 실제 실시한 T2/T3 심사비: 다수파 배심원 70%, 플랫폼 30%
- 실제 실시한 T1 심사비: 플랫폼 100%
- 보증금 잔액: 납부자에게 반환. 플랫폼 추가 수익으로 처리하지 않음

### 결과별 정산

아래 일반 결과표의 배심원 70%·플랫폼 30%는 실제 실시한 T2/T3 기준이다. T1은 배심원 없이 플랫폼 100%이며, 미예치 무심사 종료는 뒤의 별도 표를 따른다.

**구매자 승:**

| 항목 | 금액 |
|------|------|
| 구매자 | 거래대금 전액 환불 + 구매자 심사비 보증금 전액 반환 |
| 판매자 | 거래대금 $0 + 사용하지 않은 보증금 반환 |
| 분쟁 비용 출처 | 거래대금과 별개인 판매자 심사비 보증금 |
| 배심원 | 분쟁비용 × 70% |
| 플랫폼 | 분쟁비용 × 30% |

**판매자 승:**

| 항목 | 금액 |
|------|------|
| 구매자 | 거래대금 환불 $0 + 사용하지 않은 심사비 보증금 반환 |
| 판매자 | 거래대금 전액 + 판매자 심사비 보증금 전액 반환 |
| 분쟁 비용 출처 | 거래대금과 별개인 구매자 심사비 보증금 |
| 배심원 | 분쟁비용 × 70% |
| 플랫폼 | 분쟁비용 × 30% |

**부분 환불:**

기존 부분 환불 정책인 판매자 심사비 부담을 유지한다. 환불액에서 구매자 심사비를 공제하지 않는다.

| 항목 | 금액 |
|------|------|
| 구매자 | 환불 금액 + 구매자 심사비 보증금 전액 반환 |
| 판매자 | 거래대금 - 환불 금액 + 사용하지 않은 보증금 반환 |
| 분쟁 비용 출처 | 거래대금과 별개인 판매자 심사비 보증금 |
| 배심원 | 분쟁비용 × 70% |
| 플랫폼 | 분쟁비용 × 30% |

**판매자 미예치 패소 (해당 패널 시작 전):**

| 항목 | 해당 단계 처리 |
|------|----------------|
| 구매자 | 거래대금 전액 환불 + 해당 단계 심사비 보증금 전액 반환 |
| 판매자 | 거래대금 수령 $0, 미실시 단계 심사비 $0 |
| 리뷰어 | 배정·심사 없음, 보상 $0, 해당 단계 DS·정확도 평가 없음 |
| 플랫폼 | 해당 단계 분쟁 수익 $0 |
| 이전 단계 | 이미 발생한 비용·보수·담보를 보존하고 별도 정산 |

### 원금과 심사비 분리 예시

거래대금 $500, 해당 T2 심사비 $12, 양측 별도 보증금 $12씩인 **해당 단계만의 예시**다. 다른 단계 비용은 포함하지 않는다.

| 결과 | 구매자에게 지급 | 판매자에게 지급 | 리뷰어 | 플랫폼 |
|------|-----------------|-----------------|--------|--------|
| 구매자 승소 | $512 = 대금 $500 + 본인 보증금 $12 | $0 | $8.40 | $3.60 |
| 판매자 승소 | $0 | $512 = 대금 $500 + 본인 보증금 $12 | $8.40 | $3.60 |
| 판매자 미예치 종료 | $512 = 대금 $500 + 본인 보증금 $12 | $0 | $0 | $0 |

실제 심사한 두 경우 총 예치·지급액은 각각 $524이다. 미예치 종료는 판매자 보증금이 들어오지 않았으므로 총 예치·반환액이 $512이다.
승소자가 돌려받는 자기 보증금은 보상이 아니며, 승소자의 대금·환불금에서 $12를 빼지 않는다.

```

⭐⭐⭐⭐⭐ 틀림: -1 × 2.0 = -2.0
```

→ 높은 등급 = 높은 투표 가중치 = 높은 책임

## 10. 모듈화 — "분쟁의 Stripe"

### 비전

Stripe가 결제를 표준화했듯, Haggle이 분쟁 해결을 표준화.
다른 플랫폼이 API로 연결하여 즉시 분쟁 시스템 구축.

### DisputeModuleConfig

```typescript
interface DisputeModuleConfig {
  // 비용
  tier1_rate: number;             // default 0.005
  tier2_rate: number;             // default 0.02
  tier3_rate: number;             // default 0.05
  tier1_min_cents: number;        // default 300
  tier2_min_cents: number;        // default 1200
  tier3_min_cents: number;        // default 3000

  // 분배
  platform_share: number;         // default 0.30


  // 배심원
  juror_min_transactions: number;  // default 5
  juror_min_trust_score: number;   // default 50
  reviewer_counts: ReviewerCountConfig;
  max_concurrent_slots: number;    // default 3
  tier_weights: TierWeightConfig;

  // AI
  ai_plaintiff_enabled: boolean;   // default true
  ai_defendant_enabled: boolean;   // default true
  ai_expert_witness: boolean;      // default true

  // 네트워크
  use_shared_pool: boolean;        // true면 해글 공유 배심원 풀
  haggle_network_fee: number;      // 해글 네트워크 사용 수수료
  external_experts: ExpertServiceConfig[];
}
```

### 플랫폼별 설정 예시

**프리랜서 마켓플레이스:**

```typescript
{
  tier2_rate: 0.02,
  tier2_min_cents: 500,     // $5 (소액 거래 많음)
  platform_share: 0.25,     // 배심원에게 75%
  juror_min_transactions: 3, // 낮은 진입 장벽
}
```

**중고차 플랫폼:**

```typescript
{
  tier2_rate: 0.015,         // 고액이라 낮은 비율
  tier2_min_cents: 3000,     // $30
  platform_share: 0.35,      // 전문 인프라 비용
  max_concurrent_slots: 2,   // 복잡한 분쟁 = 집중
}
```

**B2B 도매:**

```typescript
{
  tier2_rate: 0.008,
  tier3_rate: 0.02,
  tier2_min_cents: 5000,     // $50
  platform_share: 0.40,
  max_concurrent_slots: 1,   // 고액 = 1건 집중
}
```

### 수익 모델

| 채널 | 설명 |
|------|------|
| 자체 P2P 거래 수수료 | GMV × 1.5% |
| 자체 분쟁 platform_share | 분쟁비용 × 30% |
| 외부 플랫폼 API 수수료 | 건당 or GMV 비율 |
| 공유 배심원 네트워크 수수료 | 네트워크 사용료 |

### 네트워크 효과

```
플랫폼 A, B, C가 해글 모듈 사용
→ 공유 배심원 풀 확대
→ 배심원 수입 다각화 (여러 플랫폼 분쟁 리뷰)
→ 더 많은 플랫폼 유치
→ 선순환
```
